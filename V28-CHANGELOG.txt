LOVE RECORD V28 · 后台任务入口与手机聊天布局修复

基于用户上传的 V27 ZIP 修改。

修复内容：
1. 新增 .github/workflows/lr-background.yml
   - 添加 GitHub Actions 手动运行入口和每 15 分钟一次的计划任务。
   - 安装 functions/package.json 中的 firebase-admin，供 scripts/lr-background-runner.js 使用。
   - 从 GitHub Actions Secret FIREBASE_SERVICE_ACCOUNT_JSON 读取服务账号，不把私钥写入仓库。
2. chat-settings-upgrade.js
   - 单聊后台活动卡片改为手机优先的纵向布局，避免说明文字被开关挤成竖排。
   - 间隔选择器强制限制在卡片宽度内。
   - 保存提示保持简短。
3. lr-group-chat-v1.js
   - 群聊后台保活选项调整为纵向布局。
   - 群聊设置保存提示改为简短文案。
4. index.html、lr-background-v1.js、sw.js
   - 更新脚本 URL 与 Service Worker 缓存版本，促使 PWA 获取新文件。

保留：
- 原有 scripts/lr-background-runner.js。
- 原有按 UID 隔离的 firestore.rules。
- 原有 Firebase 配置和其他应用文件。

部署提醒：
- ZIP 不会自动发布 Firestore Rules；仍需将 firestore.rules 内容发布到 Firebase Console → Firestore Database → Rules。
- GitHub 仓库必须有默认分支；新增 workflow 后需在 GitHub Actions 中手动运行一次。
- 仓库 Settings → Secrets and variables → Actions 中必须设置 FIREBASE_SERVICE_ACCOUNT_JSON。
- 不要把服务账号私钥 JSON 上传到仓库或 ZIP。
- 当前只完成本地静态验证，尚未连接真实 Firebase、GitHub Secret 或 Android 设备做端到端测试。
